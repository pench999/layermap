# LayerMap

YAMLで社内LANのL1・L2・L3と層間の対応を記述し、ブラウザーで編集・確認できるWebアプリです。CLIでも同じ検証・描画処理を利用できます。
データ形式は独自の `lan-example/v1` です。サンプルの機器情報はすべて架空です。

## Web版の起動

正本はDebianの `/home/kudo/layermap`。Docker EngineとDocker Composeを使います。PythonやNode.jsをホストに追加する必要はありません。

```sh
cd /home/kudo/layermap
git status --short --branch
docker-compose ps
docker compose up -d --build web
docker compose ps
```

既定の待ち受けはDebian自身の `127.0.0.1:18085` です。別のPCからはSSHトンネルを使用します。

```sh
ssh -N -L 18085:127.0.0.1:18085 kudo@<Debianのホスト名またはIP>
```

ブラウザーで <http://localhost:18085> を開きます。PuTTYを使う場合も、ローカル18085番からDebianの127.0.0.1:18085へのトンネルを設定できます。
明示的にLANへ公開する場合だけ `LAYERMAP_BIND` と `LAYERMAP_PORT` を変更してください。初期版には認証・TLS・共同編集機能がないため、既定はループバックです。

停止：

```sh
docker compose stop web
```

## ブラウザーでできること

- CodeMirrorでYAMLを編集。入力が止まって500ミリ秒後に検証・描画。
- 全レイヤー、L1物理、L2 VLAN、L3 IPの切り替え。単独表示ではレイアウトを再計算。
- 全レイヤー表示時の層間対応の表示・非表示。
- 機器を選択して、対応する各層の要素を強調表示。
- 拡大・縮小・全体表示。
- YAMLファイルの読み込み・ダウンロード、現在の表示のSVGダウンロード。
- エラーの行・列・項目パスを表示。エラーを押すと編集位置へ移動。

不正な入力・通信失敗・描画待ちの間は最後の正常な図を保持し、「現在のYAMLは未反映」または「更新待ち」を表示します。
古い応答は新しい編集を上書きしません。未反映の図のSVGダウンロードは無効になります。YAMLはエラー中でも保存できます。
編集は自動でディスクへ保存しません。「YAMLを保存」またはCtrl/Command+Sでダウンロードしてください。未保存時のファイル置き換え・ページ離脱には確認を表示します。

## 図の機器枠

L1・L2・L3それぞれで同じ機器を一つの枠にまとめます。枠内の行は物理ポートまたはインターフェースで、各行の接続点を区別して線を描きます。紫の破線も対応するインターフェース行へ接続します。L1ではメーカー・型番・シリアルNo・設置場所を同じ機器枠内に表示します。対象層のインターフェースがない機器は、その旨を表示します。YAML形式は変更していません。

L1の各ケーブルは両端ポートを結ぶ単一のSVGパスです。相手機器の方向に接続点を配置し、機器の内部を避けて直交配線します。経路選択は線の重なり・交差を減らす近似処理であり、複雑な構成で交差ゼロを保証するものではありません。C1などの図上番号と色を、ケーブルID・両端ポート・媒体・速度の一覧に対応付けます。ケーブル線または一覧へマウスを重ねるか、Tabでフォーカスすると、その一本を強調できます。

L2/L3は共有ネットワークごとにV（VLAN）・S（サブネット）・B（機器内ブリッジ）の番号と色を表示します。trunkを含め所属ごとに別の接続点を設け、下側の行から機器に近い経路を使って線の重なりと交差を抑えます。交差の背景抜きは未接続、同じネットワークへの接続点は丸印です。ネットワークの線・見出し・行内番号へのマウス操作またはTabフォーカスで所属行と配線を強調します。ブリッジはVLANを一つに統合する意味ではありません。複雑な構成で交差ゼロを保証するものではなく、YAML形式の変更はありません。

## 画面内ヘルプとサンプル

ヘッダーの「ヘルプ」から、各YAML項目の意味、機器・ポート追加、VLAN追加、入力ルールを参照できます。編集画面を離れずに開き、目次で移動して、閉じるボタンまたはEscapeで戻れます。

「サンプル構成」で基本構成・機器追加版・VLAN追加版を選び、「サンプルを読み込む」を押すとエディターと図が更新されます。ヘルプの完成例からも読み込めます。読み込み後は全レイヤー表示になります。

- 基本構成：4機器・3ケーブル・2 VLAN。
- 機器追加版：VLAN 10へHQ-PC-03を追加。5機器・4ケーブル・2 VLAN。
- VLAN追加版：HQ-PC-03を新設VLAN 30へ移動。5機器・4ケーブル・3 VLAN。

未保存の編集がある場合は置き換えの確認を表示します。取得中に編集された場合にも再確認します。読み込み失敗やキャンセル時は元のYAMLを保持します。サンプルの読み込み自体はディスク保存ではないため、編集後は「YAMLを保存」を使ってください。
追加サンプルは `samples/` に同梱します。`GET /api/samples` で一覧、`GET /api/samples/{sample_id}` で指定サンプルを取得できます。任意のファイルパスは指定できません。

## データの扱いと上限

YAMLは描画のため同じサーバーへ送信します。サーバーは永続保存せず、本文をログへ記録しません。
フロントエンドとAPIは同一オリジンで提供し、CDNや外部フォントは使いません。
構成全体の保持上限はYAML 2 MiB、機器256台、全要素10,000件です。HTTPリクエストは8 MiBまでです。保持とはブラウザーのエディター内の構成全体を指し、サーバーに永続保存する機能はありません。

表示上限は24台・200行・接続／所属400件・構成要素500件・VLAN／ブリッジ／サブネット80件、出力SVG 4 MiBです。表示中のレイヤーについて数え、trunkの各VLAN所属も接続1件として扱います。超えた場合は図を間引かず、検証済みの構成と選択肢を保持して絞り込みを案内します。描画APIの同時実行は2件までで、混雑時は429を返し、画面は最大10回まで再試行します。最新の値は GET /api/limits で取得できます。

要素数は機器、L1ポート／ケーブル、L2 VLAN／インターフェース／ブリッジ、L3サブネット／インターフェース／経路、層間対応の各レコードの合計です。所属リストは保持側のレコード数には含めず、表示側の接続数で制限します。YAMLのエイリアス・重複キーと未定義フィールドは拒否します。
ファイルは手元から読み込み、手元へダウンロードします。サーバーの任意のファイルを読む機能はありません。

## 表示範囲の絞り込み

拠点は既存の devices.location.site、機器群は任意の devices.groups で定義します。groupsは省略可能な文字列リストで、複数の群に所属できます。既存のYAMLもそのまま使えます。

```yaml
groups: [ネットワーク機器, 1F]
location:
  site: 本社
  room: サーバー室
```

画面の「表示範囲」で拠点・機器群・機器を選びます。条件はANDで適用します。機器を1台に絞ると、図が大きすぎる場合も「対応関係の起点」でポートやインターフェースを選択できます。図で行を選んだ追跡パネルの「この対応だけを表示」からも絞れます。層間対応だけを双方向に追跡し、共有する物理ポートの枝も含みます。ケーブルやVLAN／サブネットの所属先へは広げません。

範囲外へつながるケーブルは図から省略し、ケーブルID・両端ポート・相手機器の一覧を表示します。同じVLAN／サブネットの範囲外の機器も表示しません。SVGには部分表示である旨と境界ケーブル数を記載します。YAML保存は常に構成全体、SVG出力は選択範囲です。絞り込みでYAMLを書き換えません。検証は範囲外の参照も含め、必ず構成全体に実行します。

CLIも --site、--group、--device（繰り返し可）、--focus-layer と --focus-id の組で同じ絞り込みを利用できます。

```sh
docker compose run --rm generate python generate_diagram.py your-network.yaml --site 本社 --group ネットワーク機器 -o /output/hq.svg
docker compose run --rm generate python generate_diagram.py your-network.yaml --device sw01 --focus-layer l1 --focus-id sw01.p1 -o /output/port.svg
```

## 負荷試験

```sh
docker compose --profile qa run --rm benchmark
# 64台の架空YAMLを作成（実機情報は含みません）
docker compose --profile qa run --rm benchmark python bench_scale.py --example /output/scale-example.yaml
```

1 CPU・512 MiBの独立コンテナーで、少量・24台・多数行・64 VLAN trunk・256台10,000要素・長いラベル・上限超過を各3回測定します。再現用コードは bench_scale.py、結果は artifacts/scale-benchmark.json、評価は docs/scale-limits.md を参照してください。合成データによる初期評価であり、すべての配線形状で応答時間や読みやすさを保証する上限ではありません。

## Docker内の検証

```sh
docker-compose ps
docker compose build test
docker compose run --rm test
```

単体/APIテストはネットワークなし・非root・読み取り専用のソースで実行します。
ブラウザーの操作テストもDocker内のPlaywright/Chromiumで行います。

```sh
mkdir -p artifacts/browser
docker compose --profile qa build e2e
docker compose --profile qa run --rm e2e
```

ブラウザーテストは編集反映、エラー時の図面保持、レイヤー切り替え、層間対応、機器強調、ファイル読み書き、古い応答の破棄、モバイル表示を確認します。
デスクトップとモバイルの確認画像は `artifacts/browser/` に生成します。Gitには含めません。
ビルド時は依存取得のためネットワークを使用します。フロントエンドの依存は `frontend/package-lock.json`、Pythonの直接依存は `requirements.txt` で固定します。
ブラウザーテストイメージにはPlaywrightのブラウザーが含まれます。

## CLIでの図面生成

```sh
mkdir -p artifacts
docker compose run --rm generate
# 別の入力ファイル
docker compose run --rm generate python generate_diagram.py your-network.yaml -o /output/your-network.svg
# 保存監視
docker compose run --rm generate python generate_diagram.py lan-sample.yaml -o /output/lan-sample.svg --watch
```

出力は `artifacts/lan-sample.svg` です。実行ユーザーのUID/GIDが1000以外の場合は、Compose起動時に `LOCAL_UID` と `LOCAL_GID` を設定してください。

層間対応はM番号と紫の破線で示します。対応ごとに両端の行内に番号付き接続点を設け、入口・出口の経路を分離しています。線・行内番号・対応一覧をクリック、またはTabで移動してEnter/Spaceで選ぶと、その線と両端の行をまとめて強調します。選択後は「上位の行へ」「下位の行へ」で両端へ移動できます。選択はマウスを外しても保持され、同じ対応を再選択・Escape・「対応の強調を解除」で解除できます。YAML編集、表示切り替え、機器選択でも解除されます。SVG単体ではマウスまたはTabフォーカスで強調できます。交差は未接続で、複雑な構成で交差ゼロを保証するものではありません。

ポート/インターフェースの行をクリック、またはTab+Enter/Spaceで選ぶと、その行を起点に層間対応を双方向にたどり、関連する行と対応線をまとめて強調します。単一層表示や層間対応オフからの選択時は、自動で全レイヤー・層間対応オンへ切り替えます。trunkなどの多対一の対応はすべての枝を含みます。一覧をL1/L2/L3別に表示し、行名で移動、対応名で一本だけの強調へ切り替えできます。同じ起点の再選択、Escape、解除ボタン、機器選択、YAML編集・再描画、手動の表示切り替えで解除します。追跡はWebアプリの機能です。対象はYAMLの層間対応のみで、同じVLAN・サブネット・ケーブルでつながる別の行へは進みません。同じ物理ポートを共有する別VLANのL3行も含まれるため、通信可能性を示すものではありません。対応がないポートは起点一行と「定義なし」を表示します。

各行の先頭は、その層で確認する値を大きな太字で表示します。L1はポート名称（未設定ならID末尾のポート表記）、L2は実際のVLAN ID（trunkでは全タグ）、L3はIPアドレス/プレフィックスです。参照用のID・モード・所属情報・対応番号は補助情報として保持します。

## 構成と制約

- `network_model.py`：型・参照・VLAN・IP・経路の検証と、行番号付きYAML読み込み。
- `generate_diagram.py`：共通SVG描画とCLI。
- `web_app.py`：FastAPI、描画API、ビルド済みフロントエンドの配信。
- `frontend/`：React / TypeScript / CodeMirror、Playwrightテスト。

これは構成図であり、物理到達性やファイアウォールポリシーを判定するシミュレーターではありません。
L2の線はVLANへの所属・ブリッジの関係を示し、通信可能性を保証しません。大規模な構成や長いラベルでは図が読みづらくなる場合があります。
詳細は [サンプル仕様](lan-sample-README.md) を参照してください。

## 開発ルール

変更前にGit状態を確認し、変更内容を説明して承認を得ます。Docker内で検証し、必要に応じてブラウザーで確認してからcommit・GitHub pushします。
完了範囲は通常GitHub pushまでです。SSH秘密鍵、接続情報メモ、ローカル依存、生成画像はリポジトリに含めません。
