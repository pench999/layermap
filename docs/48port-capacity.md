# 48ポート3台の描画容量見直し（2026-10-21）

## 採用する上限

| 項目 | 従来 | 見直し後 |
|---|---:|---:|
| 描画するポート・IF行 | 200 | 600 |
| 描画する接続・所属 | 400 | 1,200 |
| 描画する構成要素 | 500 | 1,600 |
| SVGのUTF-8容量 | 4 MiB | 8 MiB |
| 一画面の機器 | 24 | 24（維持） |
| VLAN・bridge・subnet | 80 | 80（維持） |
| ウィザードで追加する物理ポート | 24 | 64 |

構成保持は従来どおりYAML 2 MiB・256機器・10,000要素。描画の同時処理は2件、Web/Dockerは1 CPU・512 MiB。ウィザードのポート数は入力時の制限であり、YAMLの機器ごとのポート数制限ではない。

## 対象構成とカウント

すべて合成データ。サンプル12-three-48port-switches.yamlは48ポートスイッチ3台と4 NICのホスト12台。全スイッチポートをL1/L2へ定義し、各スイッチの管理SVI、ホストのactive-backup bond・管理・業務IF/IPを含む。ホストへの48ケーブルとスイッチ間trunk 2本を描画する。

- 15機器・192物理ポート・183 L2行・39 L3行＝414行。
- 50ケーブル、接続/所属662件、構成要素720件。
- 21ホストへ増やした構成は24機器・504行・815接続/所属・918要素。
- 接続/所属にはL1ケーブル、VLAN所属、bridgeメンバー、subnet所属、層間対応を含む。trunkの各VLANは個別に数える。

通常構成の2件並列は冷起動込みwall 4.75秒、処理部分約1.70〜1.72秒/件。長いIDの600行を2件並列で処理した場合は、冷起動込みwall 7.26秒、処理部分約2.93〜2.98秒/件。単発の起動済みWeb応答と同一視しない。

候補全体のコンテナピークは91.68 MiB。追加した長いIDケースの測定コンテナピークは125.41 MiB。SVGはこのケースで約5.26 MiBとなるため、行数だけを引き上げて従来4 MiBを維持すると有効な構成が出力容量で止まる。余裕を持たせた8 MiBを採用し、APIで容量ちょうど/1 byte超過を別途検証する。

## ブラウザ確認

Chromium/Dockerで通常構成・600行・長いIDの600行について各3回、API/JSON処理、SVGのDOM挿入と2フレーム、スクロールと拡縮後の2フレームを測定する。画面外のSVGはブラウザが描画を省略し得るため、全ポートが常時実寸で描画完了する時間を示すものではない。エディターの500 ms待機は測定に含めない。

操作テストでは全414行と50ケーブル、3台の全48ポート、最後のポートの選択・層間追跡・YAML位置移動、SVI、絞り込み中の全YAML保存、モバイル、ウィザードでの52ポート追加、600行のSVG保存、601行の絞り込みを確認する。

| ケース | API 中央値 ms | DOM表示 中央値 ms | 拡縮 中央値 ms | 合計 中央値 / 最大 ms | DOM要素 |
|---|---:|---:|---:|---:|---:|
| three-48-switches-12-hosts | 234.0 | 1358.7 | 56.7 | 1664.4 / 1701.8 | 8659 |
| rows-600 | 224.2 | 3030.0 | 82.6 | 3340.3 / 3365.6 | 13389 |
| rows-600-long-ids-and-labels | 409.7 | 4129.6 | 320.4 | 4851.2 / 4880.0 | 22810 |

起動済みAPIへの通常構成2件並列は両方200/readyで完了し、wall 517.0 ms。

JSON：[Chromium/API測定](benchmarks/48port-browser-2026-10-21.json)。通常構成は約1.7秒、最長IDを多用する上限付近では約4.9秒の初回表示待ちを観測した。拡大・機器別表示で操作することを前提に、600行を運用上限として採用する。

最終検証：Docker内Python 103件・Playwright 91件がすべて成功（ブラウザ全体7.1分）。PCとモバイルの画面を目視確認し、モバイルでは明示的にYAML定義へ移動した後、約100%に拡大して48番ポートを選択できることも確認した。検証全体（再実行を含む）の稼働Webコンテナのcgroup memory.peakは159.64 MiBで、設定512 MiB以内。[検証環境記録](benchmarks/48port-environment-2026-10-21.json)。

## 再実行

    docker compose run --rm benchmark python bench_48port.py --output /output/48port-final.json
    docker compose --profile qa build e2e
    docker compose run --rm e2e npm test -- e2e/capacity.spec.ts

サンプルは画面の「48ポートスイッチ3台＋12ホスト」から読み込める。全体表示では文字が小さくなるため、拡大・機器群switches・機器別・レイヤー別表示を併用する。上限超過時は構成全体を検証し、データを間引かず絞り込みを案内する。全YAML保存は表示範囲に依存しない。

3回測定のためP95/P99は算出しない。これらは合成構成と当該ホストの測定結果であり、すべての配線形状・ブラウザ・同時利用者数に一定の応答時間を保証する値ではない。
